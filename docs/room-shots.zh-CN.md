# 房间标记截图

截图功能面向 Windows；macOS 和 Linux 保持原有普通房间标记行为。

## 使用和默认参数

双方均安装此增强版并加入同一房间后，信号和表情都会附带附近截图。旧客户端仍能看到普通标记，不能接收截图。房间设置会提示暂不能接收截图的成员。

设置 → 房间：分别开关发送和接收，选择“右下角”或“标记位置附近”；“截图范围与发送限制”调整参数。
Windows 默认允许发送和接收截图，仅在当前房间内存在支持接收截图的成员时截取。关闭发送开关可保留普通信号。

| 项目 | 默认值 |
| --- | --- |
| 初始截图 | 640 × 360 逻辑像素 |
| 连续合并间隔 | 1.2 秒 |
| 发送限制 | 任意连续 5 秒最多 5 次，信号和表情合计 |
| 超限 | 第 6 次拦截，冷却 10 秒 |
| 卡片位置 | 对应显示器右下角 |
| 卡片时长 | 10 秒，悬停暂停消失 |

取消、预览、截图更新、分片和补传不计次数。冷却期间不积压标记，不延长倒计时，不影响接收，也不会覆盖用户手动暂停状态。托盘和设置显示剩余时间。

被拦截时在当前显示器上方居中显示“你发送信号过于频繁，请稍后再试”：18 逻辑像素、金黄色 `#E4C889`，上浮渐隐，每次尝试重新触发同一行。提示不叠加，结束后移除，以便空覆盖层恢复停泊。

连续标记只提醒一次、更新同一张卡片。范围扩大时保留旧区域，包含新点及留白，图中数字标出各个位置。不同显示器分别截图，在同一张卡片中切换。切换窗口、移动/缩放窗口或滚动导致坐标失效时结束旧组。单组最多 64 个标记，超过后开始下一组。

卡片最多同时保留 3 张，小屏按可用高度进一步限制。出现时不抢键盘焦点，只有卡片范围接收点击，屏幕其他位置不受影响。点击图片打开大图，支持适应窗口、原始尺寸、滚轮缩放和拖动，Esc 关闭。新图片加载或超时期间保留上一张可读图片。关闭或过期的组不会因迟到数据再次弹出。

## 实现和边界

复用原生 `context-helper` 截图，以及房间现有密钥、AES-GCM、签名和传输。不需要 AI，不读取 AI 密钥，不增加网络主机，不保存截图历史。只有当前局部图片发送到当前房间；原生助手内部截取显示器后裁剪，整屏图不写入临时目录、不发到房间。

普通标记先发出，截图随后补齐。截图使用独立的格式 2 加密附件；原格式 1 的 1200 字节上限不变。presence 能力声明保持旧客户端兼容。

每图最多 512 KiB、单边 8192 像素、3200 万像素总量，组装和发送队列均有上限。保留区域分辨率，必要时降低 JPEG 质量，仍超限则明确报错并保留标记，不无限缩小成不可读图片。局域网每片 600 字节，中继每事件最多合并 16 片，另有限额并为普通标记保留突发容量。原有房间接收及中继上限继续生效。

标记组、更新版本、发送者和图片哈希绑定，旧版本不能覆盖新版本。接收端先校验大小、图片头、签名与哈希。丢包可以补传，45 秒截止；不保证公网秒到。

临时 JPEG 位于当前用户 `%APPDATA%\lolPing\room-shot-temp`。完成、取消、离房和退出时清理，只处理本功能命名的目录和图片，跳过重解析点和未知文件。

## 异常恢复

- 截图权限不足、助手失败、源画面变化、图片过大：标记保持可用，图片状态说明失败，下次标记可重试。
- 暂停、离房、关闭功能：取消相应任务并释放图片；迟到结果不重新出现。
- 丢包或中断：有界补传和超时，过期后释放组装内存；重连在有效期内恢复。
- 截图渲染进程崩溃：销毁故障窗口，下一次更新可重新创建。
- AI 和房间截图并发：共享捕获排除计数，避免一个任务结束时提前把自身浮层放回另一张截图。

## 验证与复用

```powershell
npm run typecheck
npm run test:helper
npm test
npm run build
node tools/room-shots-smoke/run.mjs
```

最后一条运行真实 Electron 隐藏原生窗口、程序生成的图片和加密内存房间，检查卡片、放大、缩放、Esc、悬停、崩溃恢复、设置回写和浮动提示，保存当前验收图与摘要到 仓库上级目录的 `acceptance/room-shots`（也可传入输出目录）。不抓取真实桌面、不注入鼠标键盘、不连接公共中继；临时测试入口退出后自动删除。

真实 `npm run dev` 启动可使用仅开发模式生效的 `LOLPING_HIDDEN_TEST=1`、`LOLPING_TEST_SETTINGS=<隔离目录>`，配合 `--hidden`、独立 `--user-data-dir` 检查启动。已安装程序忽略这两个环境变量。

离线测试、隐藏原生 UI、真实桌面手势、双电脑和公共中继效果分开记录。后几项须由实际试用确认，不能用模拟结果替代。

Windows 原构建使用 MSVC 传统预处理器时，已有 `CHECK` 测试中原始字符串的字符串化会产生非法转义。构建改用 `/Zc:preprocessor` 标准预处理器，保留原测试与期望。
