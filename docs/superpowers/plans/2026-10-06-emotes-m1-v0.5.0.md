# Emotes M1 (v0.5.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A League-style emote wheel on its own trigger (default Ctrl + drag), with ~32 baked, animated League emotes and the user's own images, shown locally and to room members (custom images as a placeholder until M2).

**Architecture:**
- `tools/extract-assets` gains a League effect-file (`PROP` bin) parser and a NumPy frame renderer that bakes each curated emote into a 3 s animated WebP, plus its icon and sound, and generates `src/shared/emoteCatalog.ts`.
- The C++ helper learns a second trigger; every point event says which wheel it belongs to. The overlay holds a second `Wheel` and an `EmoteStage` that plays emotes, one per owner.
- Own images are processed in the settings renderer (`ImageDecoder` + `OffscreenCanvas`), stored by `EmoteLibrary` and served over `lolping://emotes/`.
- Rooms carry a new additive `emote` message through the same routes, budgets and gates as pings.

**Tech Stack:** Electron 44, TypeScript 5.9, React 19 + Fluent UI 9, vitest 5 (node environment), C++ helper (`npm run test:helper`), Python 3.14 (`py -3.14`) with Pillow and NumPy for the tool, vgmstream + ffmpeg for sounds.

**Spec:** `docs/superpowers/specs/2026-10-06-emotes-design.md` (read it with this plan; § numbers below refer to it).

## Review Focus

1. **Multi-monitor replacement:** someone's emote is on display 1 and they emote again on display 2. Expected: the first disappears (one emote per person across all displays). → Task 6: OverlayManager sends `emote:clear` to every other overlay; verification step "replacement across displays".
2. **A custom image deleted from disk while lolPing runs:** the overlay `<img>` fails. Expected: the placeholder shows instead of a broken image. → Task 6: `EmoteStage` swaps to the placeholder on `error`; site-harness check "broken custom URL shows the placeholder".
3. **A GIF under 5 MB but 4000 × 4000 px:** decoding it for every emote would stall the overlay. Expected: refused with the animation-size error. → Task 9 test `refuses animations over 1024 px`; Task 8 test `rejects an oversize animation`.
4. **A letter as the emote key:** the key is swallowed system-wide while lolPing is on. Expected: the same "won't type in other apps" note as the custom ping key. → Task 7: the note under the emote key picker; verification step.
5. **The same bundled emote fired twice in a row:** Expected: the second starts from frame 0 and the first element is gone. → Task 6: fresh object URL per spawn; site-harness check "repeat restarts at frame 0".
