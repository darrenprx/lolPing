# Emotes M1 (v0.5.0): verification checklist

Branch `v0.5`, built and reviewed batch by batch, then given a whole-branch review. The final state passes:

| Check | Result |
|---|---|
| `npm run typecheck` | clean |
| `npm test` | 712 tests pass |
| `npm run test:helper` | 381 C++ tests pass |
| `npm run build` | passes |
| `npm run build:site` | passes |
| `npm run dist` | `lolPing-Setup-0.5.0.exe` (167 MB) |

## Verified

**Bundled emotes**
- 44 emotes are baked from League's effect files into animated WebP, at high quality with a halo opacity of 0.1, each with its own sound.
  - 4 emotes have no sound of their own and use their family sound instead: 4860, 4948, 4952, 3581.
- The tool's output is byte-identical across runs.
- Total size is 52.8 MB.
- You compared the bake against the game: Facepalm and 弱爆 (Sylas Unworthy, plus the Chinese-text variant).

**Helper (C++)**
- Covered by tests:
  - Ctrl + drag opens the emote wheel, and Alt + drag still opens the ping wheel.
  - Holding both keys passes through, the emote click works, cancel works, a custom key is swallowed, and pause stops both wheels.
- A stuck-input review traced every swallow and replay path and found no defect.

**Overlay**
Checked in a headless browser and in the built app over CDP:
- The wheel opens and closes.
- Bundled emotes play, and a repeat restarts at frame 0 with a fresh blob URL.
- Two owners show at once.
- A broken custom image shows the "?" placeholder, and so does a missing or undecodable bundled animation.
- Sizes match 80 / 150 / 300 px.
- There are no CSP violations.

**Settings**
Checked over CDP:
- The Emotes section renders in English and Chinese.
- An emote key that clashes is disabled and refused.
- A custom letter key shows the note.
- Wheel slot, centre and reset edits work, and clicking a tile previews it.
- The ping section is unchanged.

**Own images**
Checked over CDP:
- A PNG and an animated GIF import.
- A noisy photo is cut down to 128 px.
- A fake PNG is refused as the wrong type, and a duplicate is refused.
- Removing an image that's on the wheel falls back.
- The × button works, and the still icons render.
- The library re-checks everything:
  - sniffing, byte limits, 1024 px for animations and 8192 px before decoding;
  - GIF frame extents;
  - animated WebP refused as a still;
  - main computes the id.
- `lolping://emotes` refuses path traversal and any other name.
- The settings window can't be navigated away.

**Rooms**
`tools/room-peer --emotes` was run over LAN and over the relays:
- The bot's emotes show with its tag, and its own images show as "?".
- Emotes from the app reach the bot.
- A fake 0.4.0 peer shows "Can't see emotes, needs an update".

## Known and accepted

- The installer grows by about 53 MB for the emotes.
- Ctrl + drag (copy files or text) is taken over while lolPing is on. This is documented in the README and in About → Known limitations.
- Friends see your own images as "?" until M2 (v0.5.1).
- Each overlay window decodes the emote sounds up front: about 17 MB per window.
- The README screenshots and demo GIF don't show emotes yet.
